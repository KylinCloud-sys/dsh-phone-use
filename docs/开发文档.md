## 2. 通用约束与坐标模型

### 2.1 尺寸与百分比

- 画面区百分比：`s:[W,H]`。所有点击、滑动、region、verify 都基于该尺寸。
- 像素换算：`x_px = round(W * x_pct / 100)`、`y_px = round(H * y_pct / 100)`。
- `s` 必须等于截图内容图的实际像素宽高；`out` 是带标尺展示图的尺寸。
- `contentBox` 是内容在展示图中的矩形 `[left, top, right, bottom]`，不参与坐标计算。

### 2.2 原图 / 展示图分离

- `last.raw.png`：无标尺整帧，verify、像素 diff、颜色检测只使用它。
- `last.png` / `last.region.png`：带标尺展示图，只返回给模型。
- 标尺边距不属于画面区，不参与百分比计算。

### 2.3 状态失效

- 每张截图返回 `frameId`（格式 `yyyyMMddTHHmmssfff-WxH`）。
- `phone_do` 支持 `expectedS:[W,H]`、`frameId`；当前尺寸与预期不一致时返回 `stale_frame`，不执行点击。
- `phone_wake` 会重置关键帧基线；横竖屏/窗口尺寸变化也会强制整屏。

### 2.4 当前边界

- 当前 `s` 取小米互联画面子窗口的 client 区。若投屏窗口本身出现外层黑边，暂不自动裁剪 `contentCrop`；如果后续需要，应在确认有效画面区域后扩展这里，否则会误裁 App 自身的黑色 UI。

## 3. 方案一：截图百分比标尺

### 3.1 全屏标尺（`Ruler.Draw`）

- 顶部/底部：横向 `x%` 刻度。
- 左侧/右侧：纵向 `y%` 刻度。
- 每 5% 短刻度，每 10% 长刻度并标数字；四角补 `0` 和 `100`。
- 颜色：底色 `#F5F5F5`，内容边框 `#B0B0B0`，长刻度 `#5A5A5A`，短刻度 `#9A9A9A`，数字 `#333333`。
- 自适应参数（`shortSide = min(W,H)`）：
  - `margin = clamp(round(shortSide * 0.05), 16, 64)`
  - `fontSize = clamp(round(shortSide * 0.025), 9, 32)`
  - `minorLen = clamp(round(margin * 0.25), 3, 16)`
  - `majorLen = clamp(round(margin * 0.50), 5, 28)`
  - `borderWidth = max(1, round(margin * 0.06))`
- 输出：`outW = W + 2*margin`、`outH = H + 2*margin`、`contentBox = [margin, margin, margin+W, margin+H]`。
- `shortSide < 320` 的**全屏**图进入紧凑模式：字体 8px、只保留 10% 主刻度；区域图仍按 region 自适应刻度，避免小区间只剩两个标签。
- 内容区逐像素不画标尺：合成测试中 `contentDiffPixels = 0`。

### 3.2 区域标尺（全局百分比）

设 `region = (rx, ry, rw, rh)`（占全屏百分比），裁剪图尺寸 `cw × ch`：

```text
localX = (p - rx) / rw * cw
localY = (p - ry) / rh * ch
```

只在 `p ∈ [rx, rx+rw]` / `p ∈ [ry, ry+rh]` 内绘制刻度。

- 区域图外圈始终显示**全屏全局百分比**，不是区域内部 0–100。
- 自适应主刻度候选 `1% / 2% / 5%`，保证主标签间距约 ≥24px；次刻度按主刻度细分。
- 区域小于 `160×120px` 时自动保持中心扩展到至少该尺寸，并限制在画面区内。
- 区域元数据返回 `region.px`、`region.pct` 和 `coordSpace:"screen"`。
- 示例：`region:"0,50,100,20"` 的纵向标尺显示 `50/60/70`，不是 `0/10/20`。

### 3.3 DPI 与方向

- 进程声明 `SetProcessDPIAware()`，截图与 s 均使用实际像素。
- 方向按 `H >= W` 判断 `portrait`，否则 `landscape`，四边绘制逻辑与方向无关。
- 横竖屏切换后旧 `s` 作废，`expectedS`/`frameId` 校验会拒绝旧坐标。

## 4. 方案二：区域截图 + 关键帧返回策略

### 4.1 只保留两种截图

- **全屏截图**：完整画面 + 四边标尺。
- **区域截图**：变化区域/指定区域 + 全局百分比标尺。
- `image:"none"` 只是不返回图片，不是第三种截图类型；没有缩略图。

### 4.2 返回规则

| 情况 | 返回 |
|---|---|
| 无有效变化 | 仅元数据 `ch:false`，不返图 |
| 局部小变化（差异率 <30%） | 区域截图 + 全局标尺 |
| 大幅变化（差异率 ≥30%） | 全屏截图 |
| 页面切换/弹窗/横竖屏/尺寸变化 | 全屏截图 |
| 显式 `image:"full"` | 全屏原分辨率 |

### 4.3 modelBaseline

- 基线文件：`%TEMP%\dsh-phone-use\baseline.png`，状态文件：`view-state.json`。
- `modelBaseline` 是**模型最近一次实际收到的全屏图**；只有全屏图实际返回时才更新基线。
- `phone_wake`、新会话启动时清空基线；尺寸/方向变化、显式 full 后重置。
- 每次实时比较 `currentFrame` 与 `modelBaseline`，不累加中间步骤变化。

### 4.4 全屏触发条件（当前阈值）

- `diffRatio >= 0.30`。
- `opsSinceFull >= 8`（按 tap/swipe/wheel/key/text/openmenu/longpress/panel/back 等交互步骤计数，wait/clip 不计）。
- 画面尺寸或方向变化。
- 顶部标题栏区域变化明显（`HeaderRatio >= 0.50`）。
- 不连续变化块聚类 `ClusterCount >= 3`。
- 调用方显式 `image:"full"`。

diff 统计屏蔽顶部 6% 状态栏与底部 6% 手势区，避免时钟/电量噪声。

### 4.5 差异元数据

- `changeBoxPx` / `changeBoxPct` 格式为 `[left, top, right, bottom]`，变化框按变化块计算，避免零散视频噪声把框撑满。
- `screen` 返回 `[W,H]`。
- `dimensionChanged:true` 表示尺寸/方向变化并强制全屏。

## 5. 方案三：滚轮滚动

- `scripts/phone.ps1` 的 C# `Native.SendWheel` 向投屏子窗口发送 `WM_MOUSEWHEEL`；先发 `WM_MOUSEMOVE` 定位作用点。
- 1 格 = `WHEEL_DELTA`（120）；`up` 正 delta，`down` 负 delta。
- 不移动真实鼠标、不抢焦点、不使用全局 `SendInput`。
- `config.json` 的 `invertWheel:true` 可翻转方向，适配个别互联版本。
- 步骤格式：

```json
{"wheel":"down","notches":3,"at":"50,60","wait":400}
```

- `notches` 建议单次 ≤10；`at` 默认 `50,50`；`wait` 默认 400ms。
- 滚动后截图比较：有效变化返回 `scrolled:true`；连续 2–3 格无变化返回 `atEdge:true`；反向探测也不动返回 `notScrollable:true`。
- `swipe` 仅在滚轮不可用时作为兜底，不替代滚轮默认路径。

## 6. API 汇总

### 6.1 `phone_see`

```jsonc
{
  "image": "auto",          // auto | full | region | none
  "region": "0,50,100,20",  // image=region 时使用
  "grid": "ruler",          // ruler | off
  "gridStep": 10,           // 10 | 5（小图会按 24px 标签间距兜底）
  "rulerTheme": "light"     // light | dark | auto
}
```

返回包括：`s`、`out`、`contentBox`、`orientation`、`grid`、`frameId`、`expectedS`、`changeBoxPx`、`changeBoxPct`、`screen`、`mode`、`reason`；区域图额外有 `region`、`coordSpace:"screen"`。

### 6.2 `phone_do`

```jsonc
{
  "steps": [
    {"tap": "50,50"},
    {"wheel": "down", "notches": 3, "at": "50,60", "wait": 400},
    {"wait": 400}
  ],
  "grid": "ruler",
  "expectedS": [372, 844],
  "frameId": "20261123T132718-372x844"
}
```

返回包括：`s`、`did`、`hit`/`tries`/`banner`（带 verify 时）、`scrolled`/`atEdge`/`notScrollable`（带 wheel 时）、以及 `phone_see` 同款图像元数据。`expectedS` 不符返回：

```json
{"ok":false,"stale":true,"state":"stale_frame","error":"stale_frame","reason":"...","expectedS":[...],"s":[...]}
```

## 9. 已知限制 / 后续项

- **外层黑边**：`contentCrop` 暂未自动检测；当前 `s` 是投屏子窗口 client 区。如果实际投屏出现外层黑边，需要先实现内容区裁剪，否则可能误裁 App 自身黑色 UI。
- **`gridStep:5`**：标签间距不足 24px 时会回退到 10，避免重叠。
- **OCR**：只用于 `phone_wake` 的占位页状态判断，不用于普通正文读屏。
- **单窗口单手机**：当前没有多设备/多窗口支持。
- **窗口恢复**：`phone_wake` 负责恢复投屏窗口；`clip:"@restore"` 只恢复剪贴板，二者不同。
